# Production Gate Checker

> 路径约定：`RUN_DIR` 表示当前项目的 `<项目目录>/_runtime/<run-id>/`。`public/runtime/` 仅用于 Remotion 静态资源，不得作为项目中间产物目录。

## 能解决什么问题

只阻断无法正确渲染或会造成音画错位的错误。导演质量、素材证据、字幕安全区和画面复读等内容，在生成对应产物时检查一次，不在最终渲染前重新跑一遍。

## 输入

```text
RUN_DIR/scenes.json
RUN_DIR/director-plan.json
RUN_DIR/style-profile.json
RUN_DIR/subtitle-timeline.json
口播文案.md
口播音频.mp3
```

`video-brief.json`、`asset-manifest.json` 和 `visual-manifest.json` 仍可作为导演与渲染素材输入，但不属于最终硬门禁。

## 输出

```text
RUN_DIR/production-gate-report.json
```

## 渲染前硬阻断

- `RUN_DIR/scenes.json` 至少包含一个可渲染 scene
- 存在最终音频
- 存在确认后的口播文案
- 存在 TTS 服务商原生字幕时间轴，时间段合法
- 字幕时间轴的音频指纹和文案指纹与当前文件一致
- 存在 `RUN_DIR/director-plan.json`
- 存在 `RUN_DIR/style-profile.json`
- `director-plan` 匹配当前 scenes 指纹

以上任一项失败，都不允许进入 Remotion 渲染。

## 不再重复检查

以下项目仍是制作质量规则，但由对应模块在生成时负责，不再由最终 Production Gate 重复阻断：

- `video-brief.json` 字段完整性
- `visual-manifest.json` 字段、指纹、安全区和重叠风险
- 素材证据记录、每镜头素材绑定和 AI 素材元数据
- 主画面是否复读完整字幕
- 导演语义合同、renderer family、components 和 content 的完整性
- 镜头密度、视觉形式数量、动效组合和模板复用倾向

## 渲染后交付门槛

Remotion 渲染完成后必须：

- 用 ffprobe 确认成片可解码、文件大小有效、时长与尺寸正确并存在音轨
- 解码开头、最高重要度镜头和结尾共 3 帧
- 成功解码开头、最高重要度镜头和结尾共 3 个抽样帧

基础媒体检查失败时不得交付。成功交付后自动清理检查帧和报告。

## 命令

在 Shin-video 项目根目录可执行：

```bash
npm run production-gate -- --scenes=RUN_DIR/scenes.json --subtitle-timeline=RUN_DIR/subtitle-timeline.json --director-plan=RUN_DIR/director-plan.json --style-profile=RUN_DIR/style-profile.json --audio=口播音频.mp3 --voiceover=口播文案.md
```

渲染器也会在内部调用 production gate。检查失败时不允许继续渲染。

## 输出解释

- `passed: true`：允许进入 Remotion 渲染。
- `passed: false`：停止渲染，按 errors 修复。
- `warnings`：最终硬门禁默认不产生日常质量告警。
